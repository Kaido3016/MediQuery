# MediQuery — Step 10 Completion Checklist

## Objective

Prepare MediQuery for a serious buyer's technical, security, IP, privacy, product, and transaction diligence without inventing evidence.

## Completed

- [x] Created a structured buyer due-diligence request index.
- [x] Separated repository-verified facts from transaction-specific evidence.
- [x] Defined corporate/IP ownership evidence requirements.
- [x] Defined source-code and reproducibility evidence requirements.
- [x] Defined security review evidence requirements.
- [x] Defined privacy/healthcare diligence requirements.
- [x] Defined AI/ML evidence requirements and explicitly prevented documentation from being treated as proof of production AI.
- [x] Defined product/traction evidence requirements.
- [x] Defined operational evidence requirements.
- [x] Defined transaction-scope items for a definitive agreement.
- [x] Established an evidence-status rule for buyer-facing claims.

## Exit criteria

Step 10 is complete when a qualified buyer can receive a clear checklist showing what can be verified from the repository, what requires independent evidence, and what is explicitly not claimed.

All criteria are addressed by `DUE_DILIGENCE_REQUEST_INDEX.md`.

## Important limitation

This document is a diligence framework, not legal advice, a security certification, a privacy certification, or proof that every requested item has already been produced. Missing evidence must be supplied or marked missing before being represented to a buyer as complete.
